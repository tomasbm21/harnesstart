# D7 scouting — what operators hate and ask for

Lens: market / user side of BRIEF Q4 (runtime), Q5 (coordination), Q9 (observe + cost). Incumbent = Hermes. Status: unverified. X posts: **unknown** (site:x.com and site:twitter.com returned no results; did not scrape). Hermes GitHub Discussions: **disabled** (410).

## Landscape

People running Hermes, OpenClaw, and Grok Bot complain about the same bill. Skill **catalogs** (not `SKILL.md` bodies) ride every turn. **JSON schemas** dominate the prompt (Hermes default ~14.7k tokens). `MEMORY.md` and named subagents are indexes or cold functions. A named bot is not a trust zone — xAI says so, and Hermes multiplex mode leaked the default token. Models narrate “Done.” Discord specialist swarms ack-loop; Hermes then called bot-to-bot **unsupported**.

Asks: progressive disclosure with a still-discoverable index; one durable agent + skills, not N always-on copies; vault/proxy creds that never enter the sandbox; a completion **probe** independent of the acting tool; a halt that is not `pkill`; spend that can **stop**, not only chart.

## Three surprises

1. **xAI published the credential-leak claim as a rule.** “Do not use separate Bots as a security boundary.” That is not a Grok hallucination; it is the product.
2. **“Loading every tool” is the wrong picture of skills.** Bodies are already on-demand. The tax is the **index + core schemas**. Lazy-loading the index (#2045) is still an open ask because hiding names makes models miss skills.
3. **Hermes shipped Bot Mode and then told Discord fleet operators that bot-to-bot is unsupported.** Tomas’s @mention interrupt is the documented default topology, not an edge case. Adjacent RPA (UiPath vault + job state) and Discord hosting (token = blast radius) already treat this as table stakes.
