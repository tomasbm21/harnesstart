# D2 scouting — agent runtimes (lean lens)

Question: which self-hosted brain should drive the computers — adopt vs plugin vs fork? BRIEF **Q3**, **Q4**.

## Landscape

Two products actually look like an always-on **ops agent OS**: **Hermes** (Python; memory + skill learning + Kanban swarm + SSH/Docker/cloud terminal backends + CDP browser) and **OpenClaw** (Node gateway; Markdown memory + skills + Docker/Podman/SSH/OpenShell + CDP). Lean default: **adopt Hermes, plugin a VM terminal backend, do not fork.** Hermes already exposes `ctx.register_terminal_environment_provider()` so third-party sandboxes ship as plugins; built-in names (`local`, `docker`, `ssh`, …) are reserved. That is the cheapest path to R2 computers without owning a fork.

**OpenClaw** is the other honest adopt. Brain stays on the Gateway host; tools run in Docker or on SSH (remote workspace becomes canonical after seed). Browser sandbox is **not** on the SSH backend — CDP is Docker/remote-browser. DeepSeek V4 thinking+tools is documented (`reasoning_content` replay) after issue #71435.

**NVIDIA NemoClaw** is **not** a brain. Official source is [`NVIDIA/NemoClaw`](https://github.com/NVIDIA/NemoClaw) (Apache-2.0). It wraps OpenClaw (default), Hermes, or LangChain Deep Agents inside **OpenShell**. Isolation is containers (OpenShell also advertises a MicroVM driver). macOS Apple Silicon is “tested with limitations.” Treat NemoClaw as a **packaging plugin**, not a replacement runtime.

**OpenShell** (self-found) is the policy runtime NemoClaw sits on: gateway + supervisor + YAML egress/credential policy. Still not the agent loop.

**OpenHands / Goose / Letta Code / Deep Agents** are real, active, permissive (MIT/Apache) harnesses. They fail the lean “one daemon drives persistent computers” test: OpenHands is a coding controller+Docker sandbox; Goose is a local CLI (recipes/skills/MCP, Docker for *extensions*, not SSH/VM computers); Letta Code has the strongest memory/skill-learning story but **remote computers/secrets require Letta login**; Deep Agents is a LangGraph library (LangSmith-shaped prod).

**Community Hermes layers** are config/UI, not brains: Workspace is explicit **zero-fork**; `hermes-ai-team` is a guide; `hermes-devcrew` is an **archived** DeepSeek-Flash profile pack (1★); `hermes-agent-team` is a best-effort web hub last pushed 2026-05; `awesome-hermes-agents` is a 3★ index.

Coding CLIs (Aider, OpenCode, mini-SWE-agent, SWE-agent, Plandex, Codex, Crush, Pi) are instruments. Crush is **FSL-1.1-MIT** (competing-use). Plandex last push 2025-10. Wildcard glue: **Temporal** (durable Activities around LLM/tool I/O) and **Erlang/OTP** supervisors — extra platforms, not brains.

**Q3 (where the brain runs).** Lean: **one brain process on the host (claw-host Linux VM)**, computers as remote backends (SSH now, nested VM via plugin later). Brain-inside-every-VM duplicates model clients and swarm state on a 48 GB Mac. OpenShell/NemoClaw invert that (agent *in* the sandbox) — more moving parts, better policy box.

**Q4.** Adopt Hermes. Plugin VM + CDP. Fork only if the terminal-provider API cannot express a persistent hardware VM. Switching to OpenClaw is a full adopt, not a plugin. Do not fork Hermes for UI (Workspace) or team YAML (devcrew/ai-team).

## Three surprises

1. **NemoClaw is NVIDIA’s wrapper, not a runtime.** Docs: it does not replace OpenShell or the chosen agent. Express install targets DGX/WSL; Mac is limited. Unofficial `*claw` GitHub names are not this.
2. **DeepSeek V4 tool calling is a cross-harness 400.** Same `reasoning_content must be passed back` bug in OpenClaw #71435, Goose #9200/#9675, OpenHands #14177, OpenCode #24722/#25311, LangChainJS #10883. Hermes added a DSML *content* parser (`a32832e`, #15453) for a *different* failure (raw DSML in text). Fixes regress; Goose #9675 still reports streaming loss.
3. **`letta-ai/letta` is the wrong tree.** Live harness is `letta-ai/letta-code`. Devcrew (seed) is archived. `block/goose` and `All-Hands-AI/OpenHands` are redirects.
