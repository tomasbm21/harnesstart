# D5 scouting — fortress (secrets, egress, injection)

**Question:** keep agents that read untrusted content from leaking secrets or taking harmful actions (BRIEF Q7, informs Q1). **Lens:** injection happens; never give one context private data + untrusted tokens + egress.

## Landscape

**Break the trifecta, do not filter it.** Willison’s lethal trifecta (2025-06-16) plus Invariant’s GitHub MCP write-up (public issue → private repo → public PR) show this is an architecture bug. GitHub’s later Lockdown mode is documented as *not* an authorization boundary. OWASP LLM01/02/06 (2025) and the arXiv design-pattern paper (2506.08837) say the same: after untrusted input, consequential actions must be impossible.

**Where secrets live (today vs should).** This repo already copies keys from `claw.env` into Hermes `~/.hermes/.env` (`swarm/25-configure-hermes.sh`). Hermes *browser* vault is better: Fernet files under `~/.hermes/vault/` (`0600`), origin-bound CDP fill, model sees `{filled_fields, origin}`. Hermes *API* secret-sources still dump keys into `os.environ` at startup — the guest can `env`. OpenShell and strangeClaw keep real tokens on the host and give the agent placeholders; the proxy/broker injects only if host/path/method match, then redacts. Vault Agent `env_template` is the anti-pattern. PKCS#11 (SoftHSM/YubiHSM) is the wildcard for keys that should never be bytes in any VM.

**Per-agent vs per-zone.** One VM per agent is the blast-radius story a CISO wants and the RAM story R1 cannot afford if every agent has browser+secrets. Fortress default: **zones** (read / act / vault), Dual-LLM or CaMeL inside the act path, **per-zone tokens** so a research agent cannot `git push`. Qubes split-GPG is the adjacent-field picture: offline vault qube, networked client, qrexec, human confirm. Chromium site isolation is the same idea at origin granularity — do not turn it off to save RAM.

**Egress.** Deny-by-default: nftables (L3/L4, already in `host/20-provision-host.sh`) + Smokescreen or Squid (hostname ACL, SSRF) + L7 rewrite (OpenShell) for method/path. CONNECT to :443 is opaque unless you terminate TLS. OpenSnitch is the HITL analog (pop-up per binary) — prompt fatigue is a red flag.

**Approval UX (R6).** Hermes gates *shell* patterns, fail-closed at 300s, hard blocklist below `--yolo`. Issues 49167 and 51221: MCP/HTTP/SMTP writes skip the gate; an agent posted a GitHub comment despite prompt rules. Card fills in the vault *do* require the same prompt; headless cannot spend. Irreversible send/post/pay need a **code** interceptor, not a system prompt. OpenSnitch-style once/session/always will be trained into “always” unless defaults stay deny.

**Audit.** Tetragon (eBPF connect/exec, optional SIGKILL) and Squid `access.log` / OpenShell policy logs belong on the **host**, shipped off-box. A guest that escaped can rewrite its own journal. Client questionnaires (DeepInspect 38 questions, Roval SOC 2-for-agents) want identity, model version, policy version, dest, allow/deny, tamper evidence — not a chat transcript.

**What a review will ask.** Inventory of agents and tools; where keys live (not in the LLM context, not in the guest FS); per-zone least privilege; fail-closed HITL for irreversible actions; prompt-injection *red team* evidence (SOC 2 TSC do not name LLM01); nested-KVM patch level; kill switch; subprocessor list (DeepSeek). Isolation claims need published escape history, not a README.

**VM vs gVisor.** gVisor is a userspace kernel (Systrap; optional KVM platform). It is not R2. Use it only as a comparison: smaller than a microVM, weaker than KVM, nested-KVM platform is slow.

**Escapes.** Firecracker CVE-2026-5747 (virtio-PCI, opt-in `--enable-pci`, extra preconditions for host RCE; Anthropic report) and CVE-2026-1386 (jailer symlink). Historical VENOM (CVE-2015-3456) is QEMU device-model. Januscape (CVE-2026-53359 + 46113) is nested-x86 KVM shadow MMU — Claw’s Mac nested-virt requirement is the trigger class. Apple Silicon mapping is **unknown**.

## Three surprises

1. **Nested virt is on, kernel is one tick below the Januscape fix list.** This scout VM: `uname -r` = `6.12.94+`; CSA lists 6.12.95; `/sys/module/kvm_intel/parameters/nested=Y` and `kvm_amd` nested=1. Not claimed exploitable here; it is what a client will grep.
2. **Landlock is live; nftables userspace is not.** LSM=`capability,landlock,selinux`; `landlock_create_ruleset(VERSION)` returned ABI **6**; dmesg `landlock: Up and running.` `command -v nft` is empty; `/var/lib/apt/lists` has 0 files. Kernel netfilter (`nf_conntrack_*`) exists. OpenShell already chose Landlock; claw-host *intends* nftables via apt.
3. **Hermes already has origin-bound fills and still fails R6 for writes.** Vault fill is model-blind; MCP/email/HTTP are ungated. Incumbent ≠ fortress.

## Open questions

- Zone VMs vs one VM per agent on ~48 GB — who holds the browser cookies?
- Can DeepSeek-class models use opaque placeholders, or do they paste “the token is sk-…” from memory?
- Approval surface for Tomas (CLI 300s vs Discord) so fail-closed does not stall the swarm.
- Where audit logs ship so a guest cannot rewrite them.
- nftables vs TLS-inspecting proxy: privacy vs L7 allowlists.
- Does Januscape’s x86 shadow-MMU bug exist on Apple Silicon nested KVM? **unknown**.
- SoftHSM vs a real token for client v1.
